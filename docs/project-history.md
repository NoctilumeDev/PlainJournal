# 项目历史与公开边界

## Git 历史说明

PlainJournal 在本地 Git 工作区中开发，`2026-07-16` 建立可运行基线提交，后续阶段
持续在同一工作区完成并由 `docs/` 记录设计、失败、修复和验收；`2026-08-03` 完成
发布提交并公开 `v1.0.0`。

公开仓库因此只有少量早期提交，不能提供逐功能 `git bisect` 级历史，但这不替代也
不削弱可重复测试、专项脚本、数据库事实和浏览器证据。项目不会伪造、倒填或重写
过去提交；从 `v1.0.1` 起，工程治理、文档、跨平台入口和后续缺陷将按可审查主题
分别提交。

## 产品冻结

当前仓库冻结为 16GB Windows 单机约束下已经闭环的 M0-M8 单经营主体、自营 B2C
参考基线，而不是等待 Pro 补齐的基础版：

- 保留 11 个 Spring Boot 应用及既有业务闭环；
- 只修复明确缺陷和工程边界，不继续添加大型业务模块；
- 多商户、分账和 Go 异构服务不在本仓库实施，进入独立
  [PlainJournalPro](https://github.com/NoctilumeDev/PlainJournalPro)；
- `v1.0.x` 先完成后端、数据库、测试、文档与开源交付；
- 后续 `v1.1.0` 可以重构前端视觉，但不得改变所有者事实和交易状态机。

控制变量、资源边界、并发数字解释和两个仓库的职责见
[参考基线与 Pro 边界](reference-baseline-and-pro-boundary.md)。

## 证据解释

项目采用三层证据：

1. **代码与架构门禁**：静态规则、类型、PMD、SpotBugs 和依赖边界；
2. **自动化回归**：H2、Vitest、Playwright、构建和发布合同；
3. **真实运行证据**：MySQL、Redis、Nacos、RocketMQ、MinIO、多实例、故障与 F12。

提交数量只能说明历史颗粒度，不能代替这三层证据。反过来，文档中的数字也不能代替
公开 CI 和可执行脚本，因此 `v1.0.1` 开始同时保留两者。
