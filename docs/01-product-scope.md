# 首期产品范围

## 1. 产品定位

本项目首期定位为单平台自营 B2C 电商，不引入商家入驻、平台抽佣、商家结算等多租户复杂度。目标不是复制淘宝全部功能，而是围绕一条完整交易链学习分布式、高并发和最终一致性。

核心闭环：

```text
浏览商品 -> 加入购物车 -> 确认订单 -> 预占库存 -> 支付
-> 仓库履约 -> 物流追踪 -> 确认收货 -> 评价 / 售后
```

客服会话可以从商品、订单和售后单进入；通知服务贯穿支付、发货、物流和售后状态变化。

## 2. 使用角色

| 角色 | 主要能力 |
| --- | --- |
| 顾客 | 注册登录、浏览、购物车、下单、支付、查看物流、评价、售后、联系客服 |
| 运营人员 | 商品、类目、品牌、营销活动和内容维护 |
| 客服人员 | 会话接待、订单上下文查看、售后协助、已读未读处理 |
| 仓库人员 | 库存盘点、出库、发货和异常登记 |
| 财务人员 | 支付、退款和对账查询，不直接修改订单业务状态 |
| 超级管理员 | 内部账号、角色、权限、系统配置和审计查询 |

顾客账号与内部员工账号共享统一身份认证能力，但权限模型、登录入口和风控策略分开。

## 3. 前端入口

| 应用 | 定位 |
| --- | --- |
| `storefront-web` | 顾客商城，优先完成桌面响应式页面 |
| `admin-web` | 运营、仓库、财务和超级管理员后台 |
| 客服工作台 | 首期作为 `admin-web` 中的独立工作区，交互上保持单独会话窗口 |

首期不开发独立骑手 App。物流坐标由模拟上报端或测试脚本产生，真实承运商通常只提供轨迹节点，不提供持续 GPS。

## 4. 首期必须完成

### 身份与账号

- 顾客注册、登录、退出、密码重置、收货地址。
- 内部账号、角色、菜单和按钮权限。
- 登录限流、失败锁定、JWT/刷新令牌和审计日志。

### 商品与库存

- 类目、品牌、SPU、SKU、价格、图片和上下架。
- 多仓库存账、可用库存、预占、确认扣减、释放和流水。
- 商品详情与库存展示允许缓存，但数据库保留最终事实。

### 交易与支付

- 购物车、结算预览、订单创建、取消、超时关闭、订单查询。
- 首期使用可替换的模拟支付渠道，仍完整实现签名、回调幂等和退款状态机。
- 订单保存商品、价格和地址快照，后续商品修改不能改变历史订单。

### 营销价格基础

- 优惠券、红包、补贴各最多使用一份，三种类型允许叠加。
- 优惠规则支持按省、市、区六位行政区划编码限制可用地区。
- 下单锁定权益，订单取消或缺货关闭后释放，支付成功后核销。
- 订单保存原价、分类优惠、实付金额以及逐权益逐订单项分摊快照。

### 履约、物流与售后

- 仓库拣货、打包、发货和运单创建。
- 物流时间线、最新位置、异常节点和用户侧进度展示。
- 退款、退货退款、审核、退货入库和退款完成闭环。

### 客服与通知

- 顾客与平台客服一对一会话。
- 文本、图片和文件附件，消息已读未读、离线消息和历史记录。
- 会话可绑定商品、订单或售后单，但只能通过服务 API 校验访问权。
- 站内信为必做；邮件作为补充渠道，发送失败进入补偿任务。

## 5. 第二阶段增量

- 满减、限时活动和自动领取/发放活动。
- 秒杀专用入口、Redis Lua 准入、异步排队和结果查询。
- Elasticsearch 商品检索。
- Prometheus、Grafana、OpenTelemetry 链路观测。
- 真实支付沙箱与第三方物流查询接口。

## 6. 明确不做

- 多商家入驻、店铺结算和平台抽佣。
- 直播、短视频、广告竞价和复杂推荐算法。
- 跨境税费、多币种和国际仓。
- 将 Redis 库存当成最终库存，或依赖分布式锁保证最终正确性。
- 为了形式完整而一次启动全部服务；本地按功能配置分组运行。

## 7. 首期验收主线

1. 顾客选择 SKU 并提交订单。
2. 库存只有 1 件时，并发请求最多成功 1 个，库存不为负。
3. 支付回调重复到达，只产生一次有效支付结果。
4. 未支付订单到期关闭并释放预占库存。
5. 支付成功触发履约，发货后顾客能看到物流节点。
6. 顾客可从订单进入客服会话并收到回复及未读提示。
7. 售后完成后退款、订单、库存和流水可以相互核对。
